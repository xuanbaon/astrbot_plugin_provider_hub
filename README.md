# 供应商统一管理（provider_hub）

## 这个插件解决什么问题

**用 Agent（或手改文件）修改 AstrBot 的供应商后，配置里写的是一个供应商，实际运行时用的却是另一个。**

原因是 AstrBot 的供应商引用分散在三个层级，彼此不通知：

| 层级 | 文件 | 典型字段 |
| --- | --- | --- |
| 全局核心 | `data/cmd_config.json` | `agent_runner.config.model.provider_id`、`fallback_provider_ids`、`compression.provider_id`、`default_image_caption_provider_id` |
| 会话配置档 | `data/config/abconf_<uuid>.json` | 同上（会覆盖全局） |
| 各插件 | `data/config/astrbot_plugin_*_config.json` | `CREATIVE_PROVIDER_ID`、`FAST_RESPONSE_PROVIDER_ID`、`filter_provider_id`、`llm_provider_id`、`embedding_provider_id` …… |

Agent 通常只改第一层，于是：

- 日志里出现「从来没配置过」的供应商（其实是插件里写死的老供应商在跑）；
- 主模型已经换了，插件还在走旧的端点、旧的 key；
- 配置面板里改完，重启前看着生效、重启后又变回去（插件配置没跟着改）；
- 上下文压缩、图像理解、记忆提炼各用一套模型，账单对不上。

本插件把这三层的引用**全部扫出来摊在一页上**，改完点一次「一键同步」写回所有文件。

## 供应商按五类能力划分（与本体「模型提供商」面板同源）

分类口径就是 AstrBot 本体 `astrbot.core.provider.entities.ProviderType` 的五类，
判定规则照抄本体 `dashboard/services/config_service.py::list_providers`：

| 能力类型（`provider_type`） | 中文 | 页面呈现 |
| --- | --- | --- |
| `chat_completion` | 对话 | 蓝色标签 |
| `speech_to_text` | 语音转文字 | 紫色标签 |
| `text_to_speech` | 文字转语音 | 绿色标签 |
| `embedding` | 嵌入 | 橙色标签 |
| `rerank` | 重排序 | 红色标签 |

判类顺序（和本体面板一模一样，**不做字段名/适配器名猜测**）：

1. 条目自己写了 `provider_type` → 用它；
2. 否则若挂在某个 `provider_source` 下 → 继承该来源的 `provider_type`；
3. 都没有 → 视为「对话」。

`provider_type == "agent_runner"` 的条目本体面板不列出（Dify / Coze 之类的执行器），本插件同样跳过，并在扫描结果里说明跳过了几个。

- **顶部「配置文件」下拉与本体一致**：选项依次是「全部配置文件」、「默认配置文件」、「用户自建的会话配置档（显示你在 WebUI 里起的名字）」、「插件配置」。选定后只列该范围内的引用，分组标题也用配置档的名字；选「全部配置文件」则一次看全。改动会记在它所属的配置文件上，切换视图后点同步仍会一并写回，不会漏改。
- 页面顶部有五张卡片，显示每一类当前有多少个供应商；点卡片即可只看这一类的引用，再点一次取消。
- 每个引用点的下拉框**只列出同一类能力的供应商**。「对话」位置不会出现嵌入模型，「嵌入」位置不会出现 TTS 音色。鼠标悬停在选项上会说明这个供应商的类型是"条目声明"还是"继承自来源"。
- **数组型字段是标签编辑器**：`fallback_provider_ids`（回退对话模型）这类字段在原配置里本来就是数组，行上标「多值」。页面把每一项渲染成一个标签：点标签上的 **×** 移除该项，下方「＋ 添加…」下拉追加一项，「清空」一键清空整个列表。列表顺序就是回退优先级（新加的排在最后，已有顺序不会被打乱）。批量设置不会覆盖多值行，避免把列表误改成单个值。
- 批量设置时同样按类型分组（下拉里的 `optgroup`），并且**跳过类型不同的行**，不会跨类覆盖。
- 写入时后端还有一道类型守卫：即使前端被绕过，把嵌入模型提交到对话位也会被拒绝并说明原因。
- 当前值类型与字段所需类型不一致时，该行标红并显示「类型不符」，方便发现历史误配。
- 每次扫描还会用本体接口 `/api/v1/providers` 与核心内存里的供应商列表**对账**：若磁盘配置与核心内存不一致（手改过文件却没重载），扫描结果会直接提示差异数量和具体 id。


## 使用方法

1. 打开 AstrBot WebUI → 插件 → 「供应商统一管理」页面。
2. 页面上半部分是五类能力概览，下面是按「全局配置 / 配置档 / 插件」分组的引用表，每行标注**能力类型**与**用途**（主对话、回退对话模型、上下文压缩、图像理解、插件功能、向量嵌入、重排序、语音合成）。
3. 在别的窗口改过供应商（新增/删除/改类型）后，点左上角 **「重新扫描」** 刷新；扫描只读，不写盘。右上角会显示上次扫描时间。
4. 先在顶部「配置文件」里选要改的范围（默认配置 / 某个会话配置档 / 插件配置），再改下面的行。下拉上方还有一排**配置清单胶囊**（见下一节），点胶囊和选下拉是同一件事。
5. 三种改法：
   - 单值行：直接在「目标值」下拉里选；
   - 多值行（标「多值」，如回退对话模型）：点标签的 **×** 删单项，用「＋ 添加…」加项，「清空」清空整列；
   - 批量改：勾选若干行 → 顶部「批量设为」选供应商 → 「应用到勾选行」（多值行会跳过，需单独勾选）。
6. 确认顶部提示「待同步 N 处」后，点 **「一键同步」**。
7. 同步结果逐条显示，成功/失败/拒绝都有原因；原配置会备份到 `data/config_backups/provider_hub-<时间>/`。

> 本页不会自动跟随、不起定时器、不常驻监听——只有点击「一键同步」时才写盘，所以不会额外占用内存。

## 配置清单：一眼看清扫描到了哪些配置

表格上方有一排胶囊，把**扫描到的所有范围**列在一起：

- 「全部」+ 默认配置文件 + 每个会话配置档 + 插件配置，各自带**引用处数**；
- **刚建好、还没配过供应商的配置档也会出现**（处数为 0，颜色偏淡），不会让人以为扫描漏了它；
- 点任意一枚胶囊即筛选到该范围，与顶部下拉**双向同步**，两个入口永远是同一个状态。

筛选只影响显示：切到别的配置后再点「一键同步」，其他配置里的改动照样一起写回，不会漏。

## 复制配置：把一套供应商设置搬到另一个配置

新建的会话配置档默认是一套完整的空配置，一个个填模型很麻烦。点工具栏的 **「复制配置…」**：

1. 选**源配置**（默认是「默认配置文件」）和**目标配置**（默认是你当前正在看的那个配置档）；
2. 第一次点按钮是「开始复制」，再点一次变成「确认复制（覆盖目标）」——**不必担心误触**；
3. 复制完成后逐条列出写了几处、哪些位置两边本来就一致、哪些被跳过及原因，并给出目标配置的备份路径。

复制范围**只有供应商引用字段**：主对话、回退对话模型（含顺序）、上下文压缩、图像理解、语音合成、语音转文字、嵌入、重排序。平台、人格、插件开关、代理等其他设置一概不动。

几条保护：

- 目标里没有的字段**跳过**，不会硬塞；
- 源配置某处本身就是类型不符（比如嵌入模型填在对话位）时**不复制**，避免把已有的错搬过去；
- 复制前自动备份目标文件到 `data/config_backups/provider_hub-<时间>/`；
- 复制走的是本体保存接口，写完立即热重载，不需要重启 core；
- 页面上还有未同步的改动时，弹层会提醒：复制按磁盘上已有的配置进行，不包含你还没点「一键同步」的那些修改。

## 收起 / 展开分组

引用表按配置文件分组（全局、各个配置档、每个插件各一组）。插件多的时候一屏放不下，这时：

- **点分组标题**即可收起/展开该组，标题右侧的小箭头会转向；
- 工具栏的 **「全部收起」/「全部展开」** 一次处理当前列出的所有分组；
- 收起后如果这一组里有未同步的改动，标题上会挂一个「有 N 处未同步」的小标，不会因为看不见而漏改；
- 收起状态记在本机浏览器里，重新扫描、刷新页面后仍然保留。

## 撤回上一步

复制选错目标、同步改错一批，都能退回去。工具栏 **「撤回上一步」** → 弹层显示**这次要撤回的是哪一次操作**（时间 + 内容，例如「复制『默认配置文件』→『爱吃白饭』」）→ 点「确认撤回」：

- 用那次操作**写盘前的快照**整份还原涉及的配置文件，其他文件不动；
- 还原前**再备份一份当前状态**（`provider_hub-undo-<时间>`），这份备份就是「恢复」的数据来源；
- 撤回成功会**出栈**，所以可以连续点「撤回上一步」一步步往回退（保留最近 10 次）；
- 核心配置仍走保存接口还原，**立即热重载**；插件配置写回 JSON 后让插件重载；
- 只记录**本页面**发起的「一键同步」和「复制配置」，手改文件不在记录范围内；
- 备份快照被你手动删掉时，会提示并把这条记录移除，不会卡住后面的撤回。

> 提示：撤回只回滚**供应商引用字段所在的整份配置文件**（因为快照就是整份文件）。如果你的操作里同时改了供应商之外的东西，撤回会把那些一起还原到操作前的状态。

## 恢复：撤多了退回来

即 Ctrl+Y 那个动作：把刚才撤回拿走的内容再放回去，等于抵消上一次撤回。中文界面里这个动作就叫「恢复」（WPS / Office 也是这个词）。

和编辑器的 Ctrl+Z / Ctrl+Y 是同一套语义：

- 工具栏 **「恢复」**，快捷键 **Ctrl+Y**（Mac 用 ⌘+Y，也支持 **Ctrl+Shift+Z**）；撤回是 **Ctrl+Z**。
- 撤回时会把「撤回前」的状态单独备份，恢复就是把这份写回去，等于抵消上一次撤回。
- 恢复前的状态又会记回撤回记录，所以两个方向可以**来回切**，不是单向的。
- **任何新的「一键同步」或「复制配置」都会清空可恢复的记录**——和编辑器里“敲了新字就不能再恢复”一致。
- 没有可恢复的内容时按钮是灰的，悬停有说明。

> 快捷键在输入框、下拉框里不生效——那些地方把 Ctrl+Z 留给浏览器自己的撤销。

## 同步时做了什么

- **核心配置（全局 + 配置档）**：不直接写文件，而是调用 dashboard 的 `/api/config/astrbot/update`。服务端保存后会执行 `reload_pipeline_scheduler()`，流水线立即用新配置重建，**不需要重启 core，WebUI 端口也不会变**。
- **插件配置**：精确修改 JSON 字段（不经过表单，避免 schema 默认值回填），然后调用 `/api/plugin/reload` 让该插件重新加载。
- **备份**：每次同步前把涉及的文件复制到 `data/config_backups/provider_hub-<时间>/`。
- **校验**：写入前检查目标供应商必须存在于当前 `provider` 列表中、且类型与该位置匹配，否则该条被拒绝并说明原因。

## 数据存放位置

所有持久化数据都在 `data` 目录下，插件自身目录只放代码与静态页面，因此**更新或重装插件不会丢数据**：

| 内容 | 路径 |
| --- | --- |
| 配置备份 | `data/config_backups/provider_hub-<时间>/` |
| 撤回栈（最近 10 次操作的写前快照索引） | `data/plugin_data/provider_hub/undo_stack.json` |
| 恢复记录（最近 10 次撤回前的状态索引） | `data/plugin_data/provider_hub/redo_stack.json` |
| 同步历史（最近 50 条） | `data/plugin_data/provider_hub/history.jsonl` |
| 上次连通的管理端口 | `data/plugin_data/provider_hub/dashboard_port.txt` |

同步历史记录每次操作的时间、成功/失败/拒绝数量、备份路径以及逐条改动，便于事后核对「谁在什么时候把供应商改成了什么」。

## 注意事项

- **音色表默认隐藏**：`tts_switcher` 的 `voices[N].provider_id` 每个角色本来就该不同，统一没有意义。需要时勾选「显示音色表」。
- 展示型字段（`name` / `label` / `desc` 等）的值即使恰好等于某个供应商 id，也不会被当成引用，避免噪音。
- 「已停用」的供应商仍会列出，但会标注，建议不要选。
- 同步插件配置后，被重载的插件可能有一两秒不可用，属正常现象。
- 不处理 `provider_sources`（供应商源：端点 + key），只处理「引用哪个模型」。改名、换 key 请去 WebUI 的模型供应商页。
- 某类供应商数量为 0 时（例如没有配重排序模型），卡片会变灰，对应位置的引用无法选择——这属于正常状态，需要先在本体里加一个该类供应商。

## 故障排查

| 现象 | 原因 |
| --- | --- |
| 页面空白 / 提示「页面桥接脚本未加载」 | 没有从 WebUI 的插件页面打开，而是直接开了 html 文件；插件页面必须在 WebUI 的 iframe 里跑 |
| 提示「扫描失败：Failed to fetch」 | 旧版本问题，1.2.0 已修：插件页面跑在没有 `allow-same-origin` 的沙箱 iframe 里，直接 `fetch` 一律被浏览器判成跨域，现在只走父窗口的 postMessage 桥接 |
| 同步后日志里还是旧供应商 | 该引用在别的配置档里；切到对应配置档再同步一次 |
| 提示「未知供应商」 | 目标 id 在当前 `provider` 列表里不存在（可能刚被删），点「重新扫描」刷新 |
| 提示「类型不匹配」 | 该位置需要的能力类型与所选供应商不一致，检查是否选错了类 |
| 提示「配置文件不存在」 | 扫描后配置文件被移动/删除，刷新页面对应即可 |
| 扫描结果提示「与核心内存不一致」 | 有人手改过 `cmd_config.json` 但核心没重载，去桌面端重启一次核心再扫描 |
| 某类卡片是 0 | 本体里还没有配置该类供应商，先去模型供应商页新建 |
